Agentic AI & AI-Assisted Development with GitHub Copilot

From prompt to production agent — one continuous build across three intensive days
3 days · 09:00–19:00 | Intermediate | Trainer: Rajesh Gheware

A Copilot-first, practitioner-led programme taking a development team from prompting to a production-grade agentic system. Copilot on their own machines on Day 1; our browser sandbox with per-participant Kubernetes on Days 2–3. Roughly 50% theory / 50% hands-on, every block paired with labs. Token optimisation and model selection by use case taught as a Day-1 discipline.

Built as one continuous project, not a list of topics. “AskOps”, an internal engineering assistant, is scaffolded on Day 1 morning, given an agent brain by Day 1 evening, rebuilt on production frameworks and grounded in documents on Day 2, then hardened, deployed to Kubernetes and forked by every participant for their own capstone on Day 3. Every block closes on the exact limitation the next block removes.

Day 1 — Direct the Model, Build the App, Give It a Brain  own machine · GitHub Copilot

1.1Prompt & Context Engineering

Prompt anatomy & output contracts · patterns (few-shot, CoT, decomposition, self-critique) · context engineering · Copilot depth: @workspace, copilot-instructions.md, prompt files, agent mode · model behaviour compared (incl. Claude) · hallucination & drift.

Labs: prompt teardown & rewrite · schema-valid JSON contract · author your team's instructions file · break and repair a prompt.

1.2Token Optimisation & Model Selection NEW

Where tokens go (input / output / cached, hidden cost of history & tool schemas) · context budgeting · prompt caching · cheaper by design (structured output, max_tokens, deterministic code) · model selection matrix by use case (quality, latency, cost, context, tool-calling, residency) · Copilot model picker & premium-request budget · routing & cascades · measuring cost per trace.

Labs: token audit, cut 40%+ with no quality loss · same task on three model tiers, score & justify · Copilot budget exercise · cheap-first router.

1.3Python Accelerated with Copilot — the AskOps API

The Python you need: types, packages, dataclasses, exceptions, logging · type hints and pydantic · Copilot as tutor · spec-first vibe coding in agent mode · FastAPI service, async & I/O · tests as the guardrail · AI code review, when to reject · Git hygiene.

Labs: AI-tutored drills · build the AskOps package & API · pytest suite to green · accept a bad suggestion and catch it with tests · refactor + PR.

1.4Agent Foundations, Tool Use & MCP

Perceive → reason → act → observe · tool calling from scratch · a ReAct loop in ~80 lines of plain Python · stop conditions & per-run cost control · agent vs. workflow · MCP architecture, and consuming an MCP server from Copilot.

Labs: hand-rolled tool-calling agent · make it fail, fix it, report the tokens burned · drive a task through MCP in Copilot.

Day 2 — Frameworks, Teams of Agents, Grounding  browser sandbox · OpenCode

2.1LangChain & LangGraph

Sandbox + OpenCode orientation · LangChain core, LCEL, tools, agents · LangGraph state, nodes, conditional routing, cycles · checkpointers & session memory · human-in-the-loop interrupts · streaming, per-node model selection, token accounting.

Labs: port the Day-1 agent, diff the two · switch OpenCode's model backend and compare · graph with a conditional branch · kill and resume · approval interrupt.

2.2Multi-Agent — CrewAI & Google ADK

Why multiple agents, and what it costs · patterns: sequential, hierarchical, parallel fan-out, critic, router · CrewAI crews, tasks, delegation · Google ADK agents, tools, sessions, runners, evaluation · selection matrix, mixing model tiers across agents · anti-patterns.

Labs: build a crew · rebuild it in ADK and compare code, traces, spend · add a critic, then smaller worker models, re-measure · justify a framework per scenario.

2.3RAG, Vector Stores & Agent Memory

Retrieval vs. fine-tuning vs. long context, with token economics · chunking strategies & metadata · embeddings · ChromaDB / pgvector, hybrid retrieval, rerankers · agentic RAG · long-term memory with write & eviction policies · evaluation with Ragas. Labs: three chunking strategies compared on quality and tokens per answer · retriever as an agent tool · hybrid + rerank, measure the lift · long-term memory across sessions · Ragas run, tune, re-run.

Day 3 — Production, Then Yours  browser sandbox · per-participant Kubernetes

3.1MCP Servers, Production & Kubernetes

Build your own MCP server wrapping an internal-style API · Langfuse tracing, token spend & cost per trace · evals as CI gates incl. a cost-regression gate · guardrails, PII, rate limits, budget caps · timeouts, retries, fallback to a cheaper tier · containerise and deploy to Kubernetes.

Labs: build & register an MCP server · read a real trace with cost · eval suite with quality threshold + cost ceiling · guardrails + budget cap · deploy to the cluster · chaos drill.

3.2Capstone — Build, Deploy & Demo

Every participant takes a real internal use case end-to-end and builds and deploys it themselves in the sandbox on their own Kubernetes cluster access. Must include: multi-agent orchestration (choice justified) · RAG on a real document set · a self-built MCP tool · session + long-term memory · Langfuse tracing and an eval suite with a quality threshold and a cost ceiling · a justified model choice per agent · running on Kubernetes.

Cadence: pitch & architecture review, scope locked → mentored build with regular checkpoints → demos, eval & cost results, post-mortem, promotion plan. Deliverables: repository · architecture note · evaluation & cost report · demo.

At a Glance & Participant Machine Setup

Format

  • 3 consecutive days, 09:00–19:00
  • Intermediate: any language + basic Python, Git, REST
  • Max 20 participants per cohort

Models & tokens

  • GitHub Copilot — already licensed internally
  • OpenCode (opencode.ai) in the sandbox — Big Pickle, Nemotron on free usage; Qwen/Gemma on our own gateway

Participants receive

  • All lab notebooks, repositories & worked solutions
  • Prompt, context, token & model-selection, and framework cheat sheets
  • Their own capstone repository
  • Reading & further-study list

Day 1 — own machine · GitHub Copilot · corporate network

Installed and working before Day 1
  • VS Code + GitHub Copilot, signed in to the client-provided licence, agent mode enabled
  • Python 3.14 (the trainer's version, so lab repos run identically), pip or uv for virtual environments
  • git, a terminal, a modern browser
  • Network: the corporate network, since Copilot only runs there — with github.com (lab repos) and *.brainupgrade.in (model endpoint for the agent labs) reachable from it
Provided by the trainer
  • All lab repositories and the model endpoint for the agent labs
  • Confirm with client IT before kickoff: github.com and *.brainupgrade.in are reachable from the corporate network, allowlisted if needed

Days 2–3 — browser sandbox · JupyterLab · OpenCode · Kubernetes

Needed on the machine
  • A modern browser only — nothing to install; thin client to *.brainupgrade.in over HTTPS/WebSocket on guest or personal wifi (Copilot is not used on these days)
  • Sandbox login details, issued by the trainer on Day 2
Pre-provisioned per participant, persists across both days
  • JupyterLab (notebooks, datasets, solutions) · OpenCode with Big Pickle/Nemotron · Qwen/Gemma endpoint · ChromaDB/pgvector · Langfuse · Docker
  • Kubernetes cluster access with kubectl for the Day 3 labs and capstone
