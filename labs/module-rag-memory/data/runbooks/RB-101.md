# Payments API returns 502 after deploy

## Symptoms

Clients of global-bank-transaction get HTTP 502 Bad Gateway from the payments API. It starts within minutes of a release. The gateway log shows upstream connect errors, and the error rate is more than double the normal rate.

## Checks

Open the deploy pipeline and find the last release. Compare the error rate for the 30 minutes before the release and after it. Check that the new pods pass their readiness probe. A pod that is not ready gets no traffic, and the gateway returns 502.

## Fix

If the error rate doubled after the release, roll back with the release tool. Do not hot-fix in production. Confirm the error rate returns to normal within 10 minutes.

## Escalation

If the rollback does not clear the 502 errors, open a high-severity incident and page the payments on-call engineer.
