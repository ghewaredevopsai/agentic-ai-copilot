# GB-151 — Operations cannot reverse a posting booked in error

**Labels:** `story` `priority: high` `agent-ready` · **Milestone:** Client money integrity

## Description

When a posting is booked in error, there is no way to undo it. Operations send manual journal
requests to the finance team, who apply them outside the system. So our ledger and theirs disagree
until someone reconciles them by hand.

Operations need to reverse a posting through the API, given its posting id.

A reversal must leave the ledger balanced. It undoes whatever the original posting did to the two
accounts. Balances from `/api/v1/accounts/{id}/balance` must be back where they were before the
original posting. Afterwards, it must be possible to see that the posting was reversed, not never made.

## Acceptance criteria

1. `POST /api/v1/postings/{postingId}/reversal` reverses that posting.
2. After a reversal, both account balances are back to their values before the posting.
3. The reversal is visible afterwards. A reversed posting looks different from one never made, and
   from one that is still live.
4. Reversing a posting that does not exist returns a client error (4xx), not a server error.
5. Reversing a posting that is already reversed is rejected. It must not apply twice.
6. Covered by tests.

## Notes

Finance were clear: nothing is ever removed from the ledger. Whatever we do must only add records.
They left the mechanism to us. This should take about half an hour.
