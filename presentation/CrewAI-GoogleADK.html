Words used in this moduleM2

Multi-agent words

  • Multi-agent system — several agents share one job.
  • Orchestrator — decides which agent runs next.
  • Hand-off — one agent’s output, given to the next.
  • Delegation — an agent passes a job to another.
  • Manager agent — a model that plans and hands out tasks.
  • Critic — an agent that checks another’s work.

Framework words

  • Crew — CrewAI’s team of agents and tasks.
  • Sub-agent — an agent run by another agent.
  • State — named values the agents share in a run.
  • Session — one conversation: messages and state.
  • Runner — ADK’s engine; it runs an agent.
  • Event — one step, reported by the runner.
  • Eval set — test cases with expected results.

Start with one agent. Split only when its prompt or tool list grows too large.

A crew in one picture: Agent, Tool, Task, Crew2

Four objects

  • Agent — role, goal and backstory become its prompt.
  • Tool — a function. The model reads its docstring.
  • Task — one job, done by one agent.
  • Crew — the agents, the tasks and the order.
A graph says what happens next. A crew says who is on the team.

The task is the contract2

The writer has to guess
LOOSEclassify = Task( description="Classify the ticket.", expected_output="The category", agent=classifier)
  • The classifier returns a paragraph.
  • The writer guesses the team from it.
The writer gets two fixed lines
CONTRACTclassify = Task( description="Classify the ticket.", expected_output="Team: one of Accounts, Transactions, Authentication, Customer. Reason: one line.", agent=classifier) reply = Task(..., context=[classify])
expected_output is what the next task receives. Write it like a contract.

Sequential, and parallel fan-out2

Sequential — the default

  • You choose the order.
  • No extra calls. Easy to debug.

Parallel fan-out

  • Mark independent tasks async_execution=True, each with its own agent.
  • The next task lists them in context.
  • Saves time, not tokens.
Fan out only when neither task needs the other’s result.

Hierarchical process, and delegation2

What you get

  • It handles requests you did not plan for.

What you pay

  • More model calls per ticket.
  • A different path on each run.
  • Agents may pass work back and forth.
A manager is an upgrade you prove with numbers. Start sequential.

ADK in one picture: Agent, Tool, Runner, Session3

Four pieces

  • Agent — a name, a model, one instruction.
  • Tool — a plain function. Type hints become its schema.
  • Runner — runs the agent and returns events.
  • Session — the history and the state.
More setup than a crew. In return, you can see every step.

Hand-offs with names: output_key and state3

Why it helps

  • You see exactly what each agent received.
  • A wrong reply points to one named value.

What travels

  • By default, a sub-agent re-reads the whole session.
  • include_contents="none" sends only its instruction and state.
Name your hand-offs, in any framework.

Router: hand over, or call as a tool3

Evaluate the agent, not just the answer3

Two checks

  • What it did: the tool calls.
  • What it said: the final reply.

When to run

  • After every instruction or model change.
  • Keep a change only if the scores hold.
  • adk web shows each event of a failed case.
Check what the agent did, not only what it said.
