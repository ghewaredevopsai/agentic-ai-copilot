Words used in this moduleM2

Token words

  • Token — the unit a model reads. About ¾ of a word.
  • Input tokens — everything sent with a request.
  • Output tokens — the answer the model writes.
  • Cached tokens — input sent again unchanged. Billed cheaper.
  • AI credit — the unit GitHub bills Copilot usage in.

Words for the labs

  • Bundle — the set of files sent with one request.
  • Always on — a file Copilot adds to every request.
  • Cascade — cheap model first, strong one if needed.
  • Gate — the rule that decides when to escalate.
  • clientReference — the caller’s own id for a payment.

A rule has to say what it is not for2

Hard to defend

“Use the reasoning model for anything important.”

Every task is important to the person doing it. You pay the top rate for docstrings.

Easy to defend

Unit tests: default model.

Money, dates, boundaries or multi-file changes: reasoning, and read the change.

Everything else: Auto.

Review it when the model list changes.

One model, a router, or a cascade3

Escalate on a rule, not on a feeling3

Gates that work

Confidence below a threshold you measured.

A validator rejects the shape.

A test the answer must pass fails.

The input is unusual for the cheap model.

Gates that do not

“It looks unsure” — a feeling cannot be automated.

Escalate every time, or never.

A threshold nobody measured.

A cheap model that is confidently wrong cannot be cascaded. Replace it.

What to take into Module 3M2

Before you send

  • Attach files, not the repo.
  • A new chat for each task.
  • Pick the model by the cost of a quiet mistake.

When you build

  • Cheap first, with a gate you measured.
  • Counting goes to code, not a model.
  • Measure savings one way; keep money apart.
