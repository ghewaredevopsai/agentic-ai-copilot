The same record, in the language you know

Java 21 · C# 12 · TypeScript

// Java
public record Incident(String id, Severity severity) {}
var high = incidents.stream()
    .filter(i -> i.severity() == Severity.HIGH)
    .map(Incident::id).toList();

// C#
public record Incident(string Id, Severity Severity);
var high = incidents
    .Where(i => i.Severity == Severity.High)
    .Select(i => i.Id).ToList();

// TypeScript
type Incident = { id: string; severity: Severity };
const high = incidents
    .filter(i => i.severity === Severity.High)
    .map(i => i.id);

Python 3.12+

from dataclasses import dataclass

@dataclass(frozen=True)
class Incident:
    id: str
    severity: Severity

high = [i.id for i in incidents
        if i.severity == Severity.HIGH]
  • Indentation is the block. No braces, no semicolons
  • A decorator writes __init__, __eq__, __repr__ for you
  • A comprehension replaces filter + map + collect
  • Type hints read like TypeScript — and are not checked when it runs

The concepts map one to one; the Python syntax is shorter. The biggest surprise for Java and C# engineers is the last bullet: type hints are not checked when the code runs, which is why pydantic exists (tier 3).

Where your instincts are wrong

Eight differences that bite experienced engineers

Mutable defaults

def f(tags=[]) creates the list once. Every call shares it.

is vs ==

is is identity, like Java's ==. Use it only for None.

Truthiness

"", 0, [], None are all false. if not count: hides a real zero.

Hints don't check

Money(amount="ten") runs. Validation is your job, or pydantic's.

EAFP

Try it and catch the error, rather than checking first. Python's exceptions are cheap and idiomatic.

Duck typing

No implements. If it has the method, it fits. Protocol names the shape.

with blocks

try-with-resources / using, for files, locks, connections, clients.

Everything is an object

Functions and classes are values: pass them, return them, wrap them. That is a decorator.
