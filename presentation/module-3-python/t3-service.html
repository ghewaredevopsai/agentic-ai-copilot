FastAPI in one screen

The type hints are the routing, the validation and the docs

from fastapi import APIRouter, Depends

router = APIRouter()

@router.get("/runbooks/{runbook_id}",
            response_model=RunbookOut)
def get_runbook(runbook_id: str,
                store: Store = Depends(get_store)):
    try:
        return RunbookOut.of(
            store.get_runbook(runbook_id))
    except RunbookNotFound as exc:
        raise HTTPException(404, str(exc)) from exc
@router.post("/incidents", status_code=201,
             response_model=IncidentOut)
def create_incident(body: IncidentIn,
                    store: Store = Depends(get_store)):
    return store.add_incident(
        body.title, body.severity, body.service)

@router.get("/ask")
async def ask(q: str = Query(min_length=3),
              limit: int = Query(5, ge=1, le=20)):
    ...
  • @router.get ~ @GetMapping / MapGet
  • Its type decides where a parameter comes from: path, body (a model), else query
  • Depends ~ constructor injection, overridable in tests
  • response_model filters and documents the output
  • Free: 422 on bad input, and OpenAPI at /docs

Translate at the edge: HTTPException belongs in api.py only. Raised inside store.py, it makes the domain depend on the web framework.

pydantic v2

Type hints that are enforced — at the boundary

The wire contract

from pydantic import BaseModel, ConfigDict, Field

class IncidentIn(BaseModel):
    title: str = Field(min_length=5, max_length=120)
    severity: Severity   # enum: else 422
    service: str = Field(min_length=1)
    runbook_id: str | None = None

class IncidentOut(BaseModel):
    model_config = ConfigDict(from_attributes=True)
    id: str
    title: str
    severity: Severity
    opened_at: datetime

Dataclass = domain. pydantic = wire. They change for different reasons.

async and await

async def is not faster. gather is.

@router.get("/ask")
async def ask(q: str,
              store: Store = Depends(get_store)):
    runbooks, incidents = await asyncio.gather(
        sources.runbook_hits(store, q),
        sources.incident_hits(store, q),
    )
  • Awaiting I/O (httpx, async DB driver)? async def + await
  • Blocking library (requests, most SDKs)? Plain def — FastAPI runs it in a thread pool
  • Never a blocking call inside async def. It passes every functional test

JavaScript: this is Promise.all. Java: CompletableFuture.allOf. C#: Task.WhenAll. The trap row has no equivalent in Node, where there is no blocking sleep to reach for by accident. In Python there is, and an agent will use it.

Lab 3 has a test that times /ask, so sequential awaits fail visibly.

Testing a service

TestClient and dependency overrides — no server, no mocks library

# tests/conftest.py
@pytest.fixture
def client(store):
    # this test's own store
    app.dependency_overrides[get_store] = lambda: store
    with TestClient(app) as c:
        yield c          # teardown runs after yield
    app.dependency_overrides.clear()

def test_unknown_runbook_is_404(client):
    r = client.get("/api/runbooks/RB-999")
    assert r.status_code == 404
    assert "RB-999" in r.json()["detail"]

def test_ask_is_503_when_a_source_fails(client, store):
    app.dependency_overrides[get_store] = \
        lambda: WikiDown(...)
    r = client.get("/api/ask?q=deploy")
    assert r.status_code == 503

Why this design

  • Every test gets a fresh store: no leaked state
  • Failure paths are a subclass away — no mocking framework
  • yield in a fixture = setup, then teardown
  • Runs in milliseconds, in-process, in CI
This is why the spec says "no module-level store". A global cannot be overridden, so the agent's shortcut would break every test.

Specs carry constraints like "no module-level store" because the easy implementation defeats testability. A good spec tells the agent why.

Spec-first vibe coding

You write the intent and the checks. The agent types. You review.

Stage it

Ask for schemas.py first and stop. Reviewing a contract before the code built on it is where agent mode pays off.

Pin the finish line

"Do not modify tests. Finish by running python score.py 3." The agent loops against a measurable target.

Watch for

pydantic v1, except Exception, module-level state, a test edited to pass, a new dependency nobody asked for.

Vibe coding, done responsibly: natural language in, working code out, with the spec and the tests as the guardrail. Without them it is just typing faster.
