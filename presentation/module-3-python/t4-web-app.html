htmx in one picture

The server returns HTML. An attribute says where it goes.

hx-get / hx-post

Any element can make a request — on submit for a form, on click for a button.

hx-target

A CSS selector for where the response goes.

hx-swap

innerHTML by default; afterbegin adds a row to the top of a table.

A good fit: internal tools, admin pages, dashboards — anywhere a JavaScript build and a separate front-end team are overhead. A poor fit: rich client-side state, offline use, a product UI with its own front-end team.

Jinja2

Templates that escape by default — keep it that way

_results.html — a fragment

<p class="muted">Results for "{{ q }}"</p>
{% for h in runbooks %}
<div class="hit">
  <b>{{ h.title }}</b> score {{ h.score }}
  <ol>
  {% for s in steps[h.runbook_id] %}
    <li>{{ s }}</li>
  {% endfor %}
  </ol>
</div>
{% else %}
<p>No runbook matched.</p>
{% endfor %}

{% extends "base.html" %} for full pages; bare fragments for htmx. Same idea as Razor partials or Thymeleaf fragments.

Forms, and one contract

@router.post("/ui/incidents")
def ui_create(request: Request,
              title: str = Form(""),
              severity: str = Form(""),
              service: str = Form(""),
              store=Depends(get_store)):
    try:
        body = IncidentIn(title=title,
                          severity=severity,
                          service=service)
    except ValidationError:
        return templates.TemplateResponse(
            request, "_error_row.html", {...})
  • The same pydantic model validates the form and the JSON API
  • {{ q }} is escaped because the file ends in .html
  • |safe or Markup() turns that off — review every one

Validation errors return 200 with an error fragment because htmx does not swap 4xx responses into the page by default. It is deliberate, not an oversight.
