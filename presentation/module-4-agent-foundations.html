Words used in this moduleM4

Agent and tool words

  • Agent — a program where the model’s reply decides the next step.
  • Tool — a function the agent may ask to run.
  • Tool description — the name, purpose and parameters the model reads.
  • Tool call — the model’s request: this tool, these arguments.
  • Observation — the tool’s result, sent back to the model.

Loop words

  • Step — one round trip to the model.
  • Stop condition — a rule that ends the loop.
  • Step budget — the most steps one run may take.
  • Token budget — the most tokens one run may use.
  • ReAct — reason, act, observe, repeat.

An LLM is a function, not a system1

Each gap has one fix

  • Memory — the message list you keep.
  • Tools — to act, and to read fresh facts.
  • The loop — it sees each result and can correct itself.
Use it as a filter: a new part must close a gap, or you do not need it.

Who does what

  • The model works in one step only: reason.
  • Your code runs every tool and keeps the messages.
  • Each result changes the next choice.
So: most of an agent is ordinary code you can test.

A tool is a function, plus a description the model reads2

TOOL DESCRIPTION — SENT WITH EVERY REQUEST{"type": "function", "function": { "name": "search_runbooks", "description": "Find runbooks that match a symptom, such as '502 after deploy'. Use for how-to-fix questions. Not for open incidents.", "parameters": { "type": "object", "properties": { "query": {"type": "string"}, "service": {"type": "string", "enum": ["payments", "auth", "reporting"]}}, "required": ["query"]}}}

What each part does

  • name — says what the tool does.
  • description — says when to use it, and when not to.
  • parameters — JSON Schema. enum stops invented values.
The model never sees your Python code. This is all it knows.
Cost: it is sent on every call. Keep it short.

What travels on the wire2

The description is the instruction2

The model has to guess
WEAKname: get_data description: "Gets data." parameters: {"id": string}
  • What data? When? What does an id look like?
  • It guesses, and differently each run.
The model knows when to call it
CLEARname: get_runbook description: "Return the steps of one runbook by id, such as 'RB-101'. Use after search_runbooks. Not for searching." parameters: {"runbook_id": string}
Wrong tool, again and again? Rewrite the descriptions before you change the model.

The model asks. Your code decides.2

Check every tool call before you run it

  • Does the tool exist? Models invent names.
  • Do the arguments parse and match the schema?
  • Is the user allowed? Is approval needed?

When a check fails

  • Return the error as the observation. Do not crash.
  • The model usually corrects itself.

ReAct: reason, act, observe, repeat3

ONE ASKOPS RUN — THREE STEPSQUESTION Payments returns 502s since the 14:00 release. What do I do? THOUGHT I need a runbook for 502 after deploy. ACTION search_runbooks(query="502 after deploy", service="payments") OBSERVE [RB-101 Payments API returns 502 after deploy] THOUGHT I need its steps. Is an incident open? ACTION get_runbook("RB-101") · list_incidents() OBSERVE 4 steps · INC-9001 is open, linked to RB-101 ANSWER Follow RB-101. INC-9001 is already open: add to it. Do not open a new one.

What to notice

  • Each observation changes the next thought.
  • One step can call two tools.
  • It found INC-9001 only by looking.
Thought lines are optional. Actions and observations are not.

The loop, in plain Python3

agent.py — THE LOOPdef run(question): messages = [{"role": "system", "content": SYSTEM}, {"role": "user", "content": question}] for step in range(MAX_STEPS): reply = chat(messages) # reason msg = reply["choices"][0]["message"] messages.append(msg) if not msg.get("tool_calls"): # no action: return msg["content"] # the answer for call in msg["tool_calls"]: # act name = call["function"]["name"] args = json.loads(call["function"]["arguments"]) result = TOOLS[name](**args) # no checks yet messages.append({"role": "tool", # observe "tool_call_id": call["id"], "content": result}) return "Stopped: step budget spent."

How to read it

  • chat() is one HTTP POST. No framework.
  • No tool calls in the reply means: the answer.
  • The for loop is the step budget.
  • Whole file: about 100 lines, mostly tools.

The message list is the memory3

Two rules that follow

  • Keep tool results small: the top 3 runbooks, not all of them.
  • Keep runs short: each extra step pays again for all earlier ones.
  • The Copilot SDK hides this list, but still reports the tokens.

Five limits, set in code

  • Step budget — the most round trips.
  • Token budget — add up usage from each reply.
  • max_tokens — the longest reply allowed.
  • Small results — the top 3, not everything.
  • Right-sized model — compare tiers, as in Module 2.
Report tokens per run. Per call hides the growth.
agent.py — A TOKEN BUDGETused = 0 for step in range(MAX_STEPS): reply = chat(messages) used += reply["usage"]["total_tokens"] ... if used > MAX_TOKENS: return "Stopped: token budget spent." print(f"{step + 1} steps, {used} tokens")
Every reply reports its token count. Add it up. The Copilot SDK reports it too.
