MCP logical architecture: host, client, server1

USB-C for AI tools: one standard plug. Any agent can use any system that has a server.

The same three calls, for every server1

Without MCP: custom code for each system, in each agent. With MCP: one server, and every agent uses it.

The config file is the grant2

~/work/mcplab/opencode.json"mcp": { "jira": { "type": "remote", "url": "{env:JIRA_MCP_URL}", "headers": { "Authorization": "Basic {env:JIRA_MCP_AUTH}" } }, "langfuse": { ... }, "github": { ... } }, "permission": { "langfuse_delete*": "deny", "github_merge*": "deny", "github_push*": "ask" }

What to notice

  • remote — the server runs elsewhere. The agent reaches it over HTTP.
  • {env:...} — the secret stays out of the file.
  • deny removes the tool. The model never sees it.
  • Every tool costs tokens on every turn. Jira offers 5 tools, not 63.
  • A read-only token is the strongest limit of all.
One shared account puts one name in the audit log for the whole class.

What comes back is data, not instructions3

Before you connect a server

  • Read each description. Refuse vague ones.
  • Treat every result as untrusted data.
  • Use an allow-list, not a block-list.
  • Gate every irreversible action on a person.
Remember: the model’s good judgement is not a control. The gate is.
